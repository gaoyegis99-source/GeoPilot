# 方法、工具与传感器版本兼容

已发布的 MethodDefinition、ToolContract 和 SensorProductConfig 由精确 ID 与正整数版本标识。保留旧引用和规范化内容。编辑 YAML 排版或移动文件时，精确引用及内容保持相同。改变步骤顺序、工具绑定、参数语义、传感器波段或质量规则时使用新版本。QGIS 的有效端口和枚举别名随工具精确版本保留。

| 对象 | 已有运行的读取方式 | 发布约束 |
|---|---|---|
| 方法 | 通过历史方案中的方法 ID 与版本定位。 | 新版本并存。现有目录在未指定版本时可返回最高版本。历史方案传入精确版本。 |
| 工具 | 从方案步骤读取 ToolRef。每一步使用冻结的选项和绑定。 | 旧版本继续解析相同契约和有效 runner 映射。按工具版本专设映射可以保留旧版并扩展新版。 |
| 传感器 | 从历史配置引用和样本元数据追踪确切产品。 | 新资产按 sensor、product level 和 processing version 唯一匹配。相同产品键并存时，现有选择器会拒绝歧义。需要替换该键的活动配置时先评审选择规则和旧版重放。 |

## 弃用与迁移

弃用作为人工发布记录，写明精确版本、原因、建议替代版本、差异和审核依据。弃用版本仍可按历史引用重放。退役历史执行环境需要独立评估和批准，并保留配置、执行环境来源及证据。当前项目按保留历史版本的方式处理常规发布。

迁移已有任务时，从指定的历史方案新建草案，显式选择新的方法版本，补齐新的输入和参数，再走现有人工确认。旧方案、执行结果和检查记录保留原版本。缺少旧工具或配置时报告不可用，按历史发布记录恢复对应配置及运行环境。比较器核对配置和有效 QGIS 绑定。运行时语义及库版本仍需由独立样例和实际重放核验。

## 发布前检查

对已发布的原型配置快照和候选快照运行。两者均指向包含 `config/` 的原型目录。

    python scripts/methods/check_versions.py \
      --baseline /path/to/released/system-prototype-v1 \
      --candidate /path/to/candidate/system-prototype-v1

命令复用静态注册和规则检查，读取配置并写 JSON 到标准输出。退出 0 表示所有原精确版本保留，新版本在 `added` 列出。退出 1 表示配置无效、已发布版本消失或同版本内容发生变化。`VERSION_BINDING_CHANGED` 表示同一 QGIS 工具版本的有效绑定变了。发布审批需要一并复核该报告、静态检查和隔离试跑证据。 [版本复验记录](../round2/methods/p14-06.md)
