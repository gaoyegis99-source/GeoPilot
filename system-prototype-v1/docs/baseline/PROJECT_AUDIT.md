## 依赖关系、所有权和启动顺序

工作台调用本机 API，经应用服务和公共模型进入方法、资产与执行层。SQLite 由服务层写入，QGIS/Python 子进程通过请求、输出文件和日志交接。模型只生成待校验候选。具体路径和写入责任见[路径映射](../../plans/01_ARCHITECTURE/05_REPOSITORY_PATH_MAP.md)，阶段依赖沿用[原任务图](../../plans/01_ARCHITECTURE/04_DEPENDENCY_GRAPH.md)。

首批在 P0-01 后实施 P0-02 环境盘点和 P0-07 测试入口。第二批在环境与测试基线有证据后分派 P0-03 至 P0-06。Python 和 QGIS 分别读取输出做真实性检查，矢量和栅格的预期值先从人工构造的坐标及像元定义。P0 两条计算链都通过才放行 P1。

## 当前风险

- 主机 PATH 未提供 `qgis_process`，两份缓存 GIS 镜像虽有 PyQGIS 包也没有该 CLI。P0-03 需要项目隔离的 QGIS 安装或可运行 CLI 的镜像。
- 现有 Python 环境中的 Pyogrio、Rasterio 分别使用自己的 GDAL 构建。保留版本及进程证据，验证两者输出均可重开。
- 初始没有 Git 仓库。并行任务先执行文件所有权与独立审查，主控独占公共文件和进度记录。
- 16 个产品固定用例尚未运行，未以设计报告构建结果替代产品验证。
