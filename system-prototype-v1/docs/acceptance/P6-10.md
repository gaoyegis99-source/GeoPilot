## 方法与交接

测试目录的 `land-use-overlay@1` 用真实工具契约绑定、确认、暂存与请求编译验证前四步。四个工具版本均为 `1`，通过实现 `geopilot.land_use_overlay` 按 ToolRef 调用相应工作进程。[专项方法配置](../../tests/fixtures/land-use/land-use-overlay.v1.yaml)

| 固定顺序 | 步骤 | 文件交接 |
|---|---|---|
| 1 | `read_two_periods` | 分别验证两期面、来源标识和 CRS，生成两份读取快照。 |
| 2 | `map_classification_systems` | 使用两套用户给定字段和映射表，分别生成含原始编码、统一分类、时相和来源 ID 的图层。 |
| 3 | `choose_equal_area_projection` | 复用 P2 等积投影，转换两期映射图层与分析区。 |
| 4 | `overlay` | 在分析区内构建两期正面积交集，生成 `overlay_polygons` GeoPackage 和 `overlay_report` JSON。 |
| 5 | `apply_boundary_assignment` | P6-11 接续，读取分区与用户选择的面积拆分、质心或最大重叠归属。 |
| 6 | `build_change_polygons` | P6-11 接续，按最小变化面积和相邻同类合并设置形成正式变化图斑。 |
| 7 | `build_transition_matrix` | P6-11 接续，输出转移矩阵、分区统计并检查总量。 |

完整方法使用 `first_classes`、`second_classes`、`zones` 和 `analysis_extent`。正式成果为 `change_polygons`、`transition_matrix` 和 `zone_statistics`。结果规则保留 `classification_mapping_complete`、`overlay_area_balanced` 和 `transition_totals_match`。生产目录发布随这三项正式步骤与规则接通。

`preflight_land_use_step(step)` 可接在通用输入检查后。它识别 `python-land-use-map@1` 并实读两期图层，汇报已见编码或所有未映射编码。未映射时保存 `METHOD_PRECONDITION_FAILED`，`observed` 按输入角色分组，`field` 指向首个缺码映射参数。映射工作进程独立执行同样的验证。两期分类必须有各自非空且唯一的 `source_feature_id`，以整数十进制文本或原样字符串匹配显式分类表，时相为用户给定的两个不同标签。两期快照、步骤请求与确认版本提供图层来源。

`overlay_polygons` 保留 `source_feature_id`、`first_source_feature_id`、`second_source_feature_id`、`first_period`、`second_period`、`first_source_code`、`second_source_code`、`from_class`、`to_class`、`is_change` 和 `area_m2`。每个相交的正面积面部件是一行，同类组合保留以供对角转移核对。叠加在用户确认的米制等积 CRS 计算。报告分别记录每期在分析区内的覆盖、重复计量和缺口，再以两期覆盖并集的交集、图斑面积和及图斑并集核对同一预设绝对容差。源面失效、缺码或超容差时阻断，保存相应证据。
