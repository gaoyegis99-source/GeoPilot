# P4-16 检查中断与单独重查

主控签收。A 新增 `checks/recheck_service.py`、重查服务测试，并扩展预留报告事务。F 新增 `tests/checks/test_recheck.py` 的真实 HTTP 和 GIS 验证。主控接入 `checks/attempt_reports.py`、后台调度、首次检查预留、重启恢复、历史报告与取消边界。

计算和成果登记成功时，原规则版本与检查报告编号在同一事务预留。检查异常、取消或服务重启保留 `SUCCEEDED / NOT_CHECKED`，并保存未完成原因。取消在规则边界及发布事务核对。重查申请验证原规则版本与正式文件组的真实可读性和 SHA-256，领取后再次核对。重查与计算使用同一后台队列。已有待执行或活动重查返回同一报告编号。

`POST /api/runs/{id}/checks` 返回 HTTP 202 与 `report_id`。 `GET /api/runs/{id}/checks` 可按 `report_id` 查询历史，当前报告和历史编号均保留。重查使用原运行、确切确认版本和已有 GIS 文件；原检查报告兼容文件保留在运行目录。

真实 Python GIS 的中断及用户取消均保留已有成果，两步退出码均为 0。重查通过后历史旧报告仍逐值可读，原正式与中间 GeoPackage、实际日志、请求、进程清单、步骤和成果登记均保持相同。真实可读成果被改写、文件缺失、配置版本变化、检查已完成分别拒绝重查。另用真实运行复现首次报告兼容文件已链接而 SQLite 未提交时服务退出，重启发布原预留编号的中断报告，清理未提交文件，全部三个实际成功步骤与正式成果保持可读。
