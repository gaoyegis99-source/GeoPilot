## 实现与接口

`geopilot.checks.artifact_checks.check_run_artifacts(database_path, run_id, *, rules=None)` 返回 `tuple[ArtifactCheckResult, ...]`。每条记录包含规则名、`artifact` 阶段、字段、严重程度、判定、观察值、期望和说明。`passed` 取 `True`、`False` 或 `None`，分别表示通过、失败和未执行。规则严重程度可配置为 `blocking` 或 `warning`。

`artifact_integrity` 在成功执行的运行中核对精确方案版本、预期角色、产出步骤与已登记输入版本，重开相对路径指向的实际成果并验证文件组 SHA-256。方法规则按确认方案的名称顺序执行。`rules=None` 使用现有 `output_exists`、`output_clipped_to_analysis_extent` 和 `detail_count_matches_summary`，显式映射按同名匹配，`rules={}` 仅检查完整性。范围或栅格规则使用运行目录中的暂存资产，并核对其精确图层和内容指纹。

`vector_rule` 检查实际几何，支持可选的范围和精确要素数。范围要求已知等价 CRS，采用 Shapely `covers`，包含范围边界。既有道路方法检查裁回范围与明细 ID，CSV 的逐行数量和全部 ID 按整数及对象标识精确核对。`raster_match_rule` 以实际暂存栅格为参考，比较 CRS、网格变换、分辨率、尺寸、波段、NoData 与掩膜，再按参考栅格块读取共同有效值。按最外一圈和内部像元分别记录差异。边界与内部计数中的 `common_valid_pixels` 要求该位置的所有波段共同有效，掩膜与数值差异按波段计数。

`NumericTolerance` 要求显式的非负有限绝对值、相对值和来源。连续值比较使用 `abs(observed - expected) <= absolute + relative * abs(expected)`。P0-06 的整数 DN 和掩膜使用精确比较。DEM 参考为手工平面，测试点高程 `160 m`，取该处的一个 Float32 ULP `2**-16 m`，相对容差为 `0`。修改一个 ULP 通过，修改两个 ULP 失败。[栅格手工参考](../../tests/fixtures/raster/expected.json) · [矢量手工参考](../../tests/fixtures/vector/expected.json)

新增 `src/geopilot/checks/artifact_checks.py`、`tests/checks/test_artifact_checks.py`、本报告和专项 JUnit。检查从只读 SQLite 事务获取记录，并通过本机文件证据生成判定。报告汇总、双状态更新和 T16 的 HTTP 接入由 P4-15 负责。

实现前因缺少 `geopilot.checks.artifact_checks` 退出 `2`。补充边缘与内部断言后，首轮因缺少分项失败。最终 `14 passed in 2.09s`，JUnit 无失败、错误或跳过。[专项 JUnit](../../artifacts/test-results/p4-14-junit.xml)

关联回归先得到 `45 passed, 5 skipped`，跳过项需要真实 QGIS 入口。启用项目隔离的 `qgis_process` 后，关联回归 `50 passed in 20.36s`，包括实际缓冲过程证据。[QGIS 环境](../baseline/ENVIRONMENT.md)

| 实际文件证据 | 结果 |
|---|---|
| P0-05 裁回目标和真实 CSV | 六条目标、各分区计数与未分配项通过。相同总数的错误 ID 与范围外目标分别在对应规则失败。 |
| GeoPackage 自相交面 | 成果文件和图层可重开，几何规则记录 1 条无效要素。 |
| 登记后修改 GeoPackage | SHA-256 与登记值不同，完整性失败，配置规则记录未执行。 |
| P0-06 两波段 GeoTIFF | 完整参考含 10 个共同有效像元，其中边缘 9、内部 1。边缘或内部单像元 DN 改动各定位 1 处，单波段 NoData 改动定位 1 处掩膜差异，仿射错位使网格失败并跳过像元比较。 |
| P0-06 平面 DEM | 一个 ULP 通过，两个 ULP 失败，容差来源保存到期望证据。 |
| 可读属性筛选成果 | 实际 GeoPackage 含 `building-west` 一条，配置预期为两条时同一规则可分别输出阻断或警告。检查返回后运行记录保持 `SUCCEEDED / CHECKING`。 |

T16 可在属性筛选方法的 `check_rules` 加入 `filtered_feature_count`，对应映射 `vector_rule("filtered_feature_count", "filtered_features", expected_count=2)`。实际筛选条件为 `source_feature_id == "building-west"`，输出期望角色为 `filtered_features`。

栅格比较以相同网格为前提。不同网格先记录差异，像元检查标为未执行。方法需要自行选择与结果物理意义相符的参考资产及容差。文件状态核对覆盖本次读取期间可观测的变更，外部进程仍可在检查完成后移动或改写文件。
