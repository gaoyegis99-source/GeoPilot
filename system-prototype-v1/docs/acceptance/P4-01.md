# P4-01 运行与步骤持久化模型

Agent-D 建议 `REVIEW`。P1-01、P2-10 与 P3 阶段已验收。按 V2.0 §8.1 与 §8.7，`Run` 保存精确方案版本和独立的执行、检查状态。`ExecutionStatus` 沿用单步协议，`CheckStatus` 包含 `NOT_CHECKED`、`CHECKING`、`PASSED`、`WARNING`、`FAILED`。取消意图、当前步骤、当前报告及结构化错误均可单独保存。

`RunStep` 按 `(run_id, step_key)` 标识，`position` 从 0 开始且在同一运行中唯一。请求与结果复用 `StepRequest`、`StepResult`，校验其运行和步骤身份、结果状态、日志引用及记录时间顺序。可为排队及中断记录省略尚未产生的请求、结果、日志和时间。

SQLite v2 向 `run` 追加 `cancel_requested`、`current_step` 和 `current_report_id`，默认分别为 `0`、`NULL`、`NULL`。旧版显式列插入可继续使用，`run` 对精确方案版本的外键保留。`run_step` 存储有序状态、JSON 请求和结果、日志路径及时间。迁移与 `user_version` 在同一事务提交，既有运行的步骤证据仍可从原运行目录读取。

`geopilot.persistence.run_repository` 提供 `insert_run`、`get_run`、`update_run`、`save_run_step`、`get_run_step` 和 `list_run_steps`。函数使用调用方提供的 `open_database` 连接。生命周期读改写可在同一个 `BEGIN IMMEDIATE` 中完成，提交或回滚由调用方负责。`update_run` 保持方案、目录及创建时间，`save_run_step` 保持步骤顺序。
