# P1-03 本地矢量读取器

2026-11-11（Asia/Shanghai），主控实现。前置 P0-04、P0-05、P1-02 已验收。

`read_vector_metadata(path)` 读取本机 GeoJSON 或 Shapefile。路径和实际驱动须相符。读取器返回驱动、几何类型、CRS、范围、要素数、字段类型和逐字段缺失数。未定义或无法解析的 CRS 以 `crs: null` 和 `CRS_UNKNOWN` 记录，可读数据可继续登记。文件或图层读取错误使用 `SourceReadError` 定位。`read_layer_metadata` 同样用于 GeoPackage 指定层，区分矢量和非空间表。

| 实际样本 | 核对结果 |
|---|---|
| 两点 GeoJSON | EPSG:4326、`Point`、2 要素，范围 `[117, 40, 117.25, 40.5]`，`label` 缺失 1、`value` 缺失 0 |
| 无 `.prj` 的 Shapefile | 1 要素，`crs: null`、`CRS_UNKNOWN`，保留原始坐标范围 |
| 无属性字段的 GeoJSON | 1 要素，字段列表为空 |
| P0 `road-buffer.gpkg` 的 `roads` | EPSG:32650、`LineString`、3 要素，`source_feature_id` 无缺失 |
| 缺失及无效 GeoJSON | `SOURCE_UNREADABLE`、`phase=data`、`field=source.path` |

先创建 `tests/data_adapters/test_vector_reader.py`，运行指定命令返回 `2`，报 `ModuleNotFoundError: No module named 'geopilot.data'`。随后实现 `src/geopilot/data/vector_reader.py` 与三类读取器共用的 `src/geopilot/data/errors.py`。运行 `python -m pytest tests/data_adapters/test_vector_reader.py -q --junitxml=artifacts/test-results/p1-03-junit.xml`，`6 passed in 0.59s`、退出 `0`。[JUnit](../../artifacts/test-results/p1-03-junit.xml)

交叉审查发现 Pyogrio 会把特定相对文件名解释为 URI，`!` 会改变归档路径解析。新增两条回归，在交给 GDAL 前拦截验证，原实现两条均失败，未发起远程请求。`local_ogr_path` 现先解析真实绝对文件，并拒绝被解析为虚拟路径的表示。重跑同一专项命令，`8 passed in 0.52s`，更新后的 JUnit 记录 8 项。

实现沿用冻结的元数据和错误接口。无数据库、HTTP API 或产品固定用例变更。逐字段缺失数需要读取属性列，统计的内存与属性表大小相关。
