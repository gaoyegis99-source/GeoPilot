# P9-07 模型错误、超时与重试

状态 REVIEW，待主控验收。执行角色 Agent-G。

`request_model_suggestion(provider, request, *, timeout=30.0, max_attempts=2, protected_literals=())` 先序列化并扫描完整请求。每次尝试使用同一份已扫描 JSON 的独立副本，按同一候选快照解析回复。允许 1–3 次尝试，已归类的超时、网络错误、限流和瞬时服务不可用可以重试。边界拒绝和解析失败立即返回；调用方可分别处理 `DataBoundaryError`、`ModelProviderError` 和 `ModelResponseError`。草稿与正式运行由原有本机服务管理。

`OllamaModelProvider(model, *, port=11434)` 通过直接的 IPv4 环回 HTTP 连接调用 `/api/generate`，关闭流式输出并对每次 HTTP 尝试设置截止时间。模型标识附加 `:local`，由支持该来源修饰的 Ollama 拒绝远程模型别名。请求的唯一任务内容为通过扫描的 `prompt`；系统指令和基础回复 Schema 固定，完整回复仍由 P9-05 校验。适配器使用已安装的本机模型并复用本机守护进程。 [生成接口](https://docs.ollama.com/api/generate) · [结构化输出](https://docs.ollama.com/capabilities/structured-outputs) · [本机模型来源实现](https://github.com/ollama/ollama/blob/main/server/routes.go)

先行测试在缺少 `geopilot.llm.client` 时退出 2。最终专项 `48 passed in 1.48s`，联合回归 `240 passed in 8.95s`。独立环回服务捕获了完整 HTTP 字节，核对两次限流重试请求一致、代理和跳转目标零请求，以及边界拒绝时零连接。实际连接拒绝、等待超时、持续分段响应越过截止时间、无效 JSON 与保留 SQLite 草稿也通过了验证。

通过 `PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 python -` 登记 P0 合成 GeoPackage 的两个图层，以 `request_model_suggestion(OllamaModelProvider('qwen3:4b-instruct'), request, timeout=60.0, max_attempts=1, protected_literals=protected)` 实跑 Ollama 0.24.0。发送的内容为合成资产白名单摘要与本机候选标识。最终返回 `spatial-select-and-clip` v1、`spatial_relation=within`、缺项为空，用时 1.215 秒。本机复核得到无问题的草稿预览，SQLite 的方案和运行行数均为零。

实际 Ollama 对完整 Pydantic Schema 返回 HTTP 500，因此适配器发送只包含基本 JSON 类型的固定 Schema。首次成功建议曾复述提示中的 `inputs.roads` 示例，本机未采纳该缺项。删除具体示例并明确使用候选角色与 `READY` 状态后完成最终复跑。实际模型验证覆盖当前本机守护进程和一个合成任务。
