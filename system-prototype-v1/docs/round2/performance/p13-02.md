## 正常执行入口

在服务环境设置 `GEOPILOT_TELEMETRY=1`。同步确认计划和服务领取计划均沿用 V1 运行、检查及成果登记。进入执行前先验证工作目录及已暂存快照。运行终止后，旁路记录由单一有界后台队列发布到运行目录内的 `.geopilot-telemetry.json`。格式版本为 1。文件写完后原子建立最终名称，已有文件和符号链接不会被覆盖。该文件权限为 0600。启用遥测时，消费者可在观察到终态后限时轮询此文件，收到后核对 `schema_version` 和 `run_id`。超时未见文件应标记发布缺失。发布故障、队列满或进程在写入前退出时可以缺失整个侧文件。关闭遥测时不创建文件。

独立工具基准可显式通过 `record_run(workdir, run_id)` 启动记录。在此上下文中调用现有适配器，保持其请求的 `run_id` 与上下文相同，并使用绝对的工作目录路径。生产重试采用 V1 新运行目录及新 ID，重查沿用历史成果，既有遥测文件不重写。

| 字段 | 口径 |
|---|---|
| run `wall_ns` | 从已暂存快照进入逐步执行到执行、登记和检查终态返回的单调钟。另有 `execute_steps_wall_ns` 和 `finalize_wall_ns`，后者含成果登记和检查。 |
| run `queue_wall_ns` | 领取模式下从已入库 `created_at` 到快照读取后的 UTC 差，含执行准备的一小段。同步模式没有排队时间。提交到持久终态的端到端单调钟由调用方包住提交及终态确认测量。 |
| step `wall_ns` | 适配器准备输入、启动命令、核验输出和写步骤结果的单调钟。保留 `step_key`、工具契约 ID 和精确版本、运行环境版本、步骤状态和退出码。 |
| process `wall_ns` | 本地命令启动和等待的单调钟，含既有超时及取消终止过程。QGIS 帮助查询为 `discovery`，计算为 `execute`。 |
| `cpu_ns`、`disk_read_bytes`、`disk_write_bytes` | Linux /proc 在有效时刻观测到的进程会话累计量下界，状态为 `partial`。CPU 为用户与内核时间，I/O 为存储层字节，缓存命中时可以真实为零。运行及步骤对顺序命令求和。 |
| `peak_rss_bytes` | 同时在场的会话内进程 RSS 总和的采样峰值，运行及步骤取各顺序命令最大值。至少两次完整采样，且首尾均在两倍采样间隔内时为 `sampled`，覆盖不足时为 `partial`。共享内存页可能重复计入，短峰可能落在采样间隔内。 |
| `resources` | 每项记录 `status`、`value`、`reason`，运行和步骤另有 `observed_processes` 与 `processes`，用于判断有读数的命令数和已启动命令总数。缺失值为 `unavailable` 与 JSON `null`。 |

采样线程按 50 ms 等待，最多遍历 64 个进程和 256 个线程。启动时打开一枚本机 /proc 目录 FD 固定进程身份，后续读取均在后台。退出时仅停止采样，不等待采样线程或发布队列。无法打开 /proc、缺权限、进程过短或覆盖不全时保留实际退出、版本和耗时。采样只覆盖同一进程会话中可见的后代。采样上限、进程退出和脱离会话都可能降低覆盖。内存峰值和 CPU/I/O 下界只在相同口径下比较。

外部容器的 QGIS 调用可设置 `GEOPILOT_TELEMETRY_QGIS_SCOPE=container`。采样亦会识别可见的常用容器客户端。容器真实计算进程不在本地命令进程会话内时，进程资源标为 `external_container` 与 `unavailable`。这种调用仍保留命令墙钟、退出码和 QGIS 返回的运行时版本。当前环境没有采集该 Docker 容器的 cgroup 计数；后续基准可在原生 QGIS 环境采集对应进程数据，或另行接入可归属到单次运行的容器计数。

## 真实样本与采样开销

固定道路 `road-buffer-statistics@2` 的 `road-first` 通过七步运行及实际结果检查，原始侧文件记录 11 个命令。步骤键和工具版本逐项与计划快照吻合，正式成果清单没有侧文件。该次执行与收尾共 16.592 秒，其中登记与检查 0.471 秒。三个 Python 执行命令各取得 13 次采样，八个 QGIS 容器命令显式缺失资源，均保留阶段、退出码和版本。运行资源聚合覆盖 3/11 个命令，状态为 `partial`，有采样范围内的 CPU 观测下界为 9.54 秒、RSS 观测峰值 162,603,008 字节、写入 872,448 字节。 [真实道路侧文件](p13-02-road-sidecar.json)

采样开销对照直接运行现有 `capture_process`，命令为当前 Python 的 `-c` 工作负载，持续使用 0.10 秒 CPU 并等待 0.14 秒。逐轮交换关闭/开启顺序，前两轮预热，随后每组七次，全部退出 0。开启组的命令均取得至少两次采样。墙钟中位数由 265.52 ms 变为 266.16 ms，监督进程 CPU 中位数由 1.18 ms 变为 6.24 ms。监督进程 CPU 口径含采样线程。对照用于记录本机短命令的采样成本，真实方法的多档性能由后续任务分组测量。 [原始开销记录](p13-02-overhead.json)
