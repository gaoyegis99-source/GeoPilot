## 等待目标和测量方式

提交已确认方案到状态接口首次观察到 `SUCCEEDED/PASSED` 为完整任务等待时间，包含排队、计算、成果登记与检查。参考条件为本机 Linux、每个 SQLite 项目一个活动槽，开始计时前无排队任务。资产登记、草稿确认和下载在计时区间外，正式样本仍须通过独立成果与来源校验。以通过校验的试次计算最近秩 P95，每档冷暖各两次预热和五次正式。五次正式样本的 P95 等于组内最大值。超时、失败和缺失仍计入试次，发布性能验收须每个正式样本通过且每组 P95 达标。 [P13 性能政策](../../../plans-round2/05_ACCEPTANCE/03_PERFORMANCE_POLICY.md) · [Google SRE 服务目标方法](https://sre.google/workbook/implementing-slos/)

工作台在提交后呈现状态，长任务持续显示真实阶段和耗时，支持刷新恢复和取消。公开交互研究的秒级反馈建议用于界面设计，GIS 完整任务的等待预算依据本项目实测制定。运行时沿用工具步骤的独立限时。 [Nielsen 交互响应研究](https://www.nngroup.com/articles/response-times-3-important-limits/) · [长任务技术验收](../user-research/p16-05-long-task-verification.md)

冷态使用新应用进程和独立项目，暖态复用应用及已确认方案。操作系统页缓存未清理。复验在 16 物理核 Intel Xeon E5-2667 v4 参考机和 tmpfs 工作目录运行，各族使用独立 CPU 集合。矢量采用 QGIS 3.44.15、宿主 Python 3.13.13，栅格使用固定 QGIS 3.44.15 运行镜像和 Python 3.12，路网使用 Python 3.13.13。所列秒数是这些样本和环境的发布验收上限。
