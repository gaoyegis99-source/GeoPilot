# P13-08 单活动执行与容量边界

## 决策

第二轮继续按解析后的本机 SQLite 项目路径运行一个调度器和一个活动槽。计算、成果登记、检查和重新检查使用同一槽。可同时处理浏览器交互和状态读取。运行提交可能复用同一数据库中其他任务或方案的活动运行 ID，重试也经过相同入口。直接辅助执行、数据库路径别名和远程文件系统不在已验证的部署范围内。 [P12-10 调度契约](../audit/concurrency-model.md) · [运行提交源码](../../../src/geopilot/runs/service.py) · [调度源码](../../../src/geopilot/scheduler/loop.py)

## 重新评估条件与回滚

先定义同时提交时每个任务和方案的运行 ID 语义，以及重查排队与取消的边界。两活动槽的隔离试验需使用不同运行目录、QGIS 配置目录和可追踪的进程身份，覆盖同项目的领取竞争、取消、超时、重启、结果发布和失效回收。对于外部 daemon，按每次运行的真实容器身份观测终止和清理，再允许释放执行槽。

容量试验可在同一固定后端比较一个和两个活动槽。用独立结果参考核验代表性小、中、大 GIS 输入，保留全部失败和未完整采样。观察端到端吞吐与分位延迟、完整进程树 RSS、CPU、磁盘占用和 I/O、SQLite 忙等待、状态读取、取消及重启重叠。用目标部署的实际配额和保留空间判断是否有提升。当前每项目的运行建议为一个活动槽。128 条队列记录是压测规模，容量上限待测。

本项只交付决策和证据复算，不改调度、API 或数据库。撤销决策与复算提交即可回滚本项。未来若单独上线多活动槽，回滚应先停止领取并排空或按已有语义终止活动运行，验证工作进程退出后以单活动配置启动，再复核排队任务、报告和成果状态。
