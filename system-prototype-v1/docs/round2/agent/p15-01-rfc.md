# P15-01 任务澄清契约

主控批准版本 1。澄清依据现有的版本化方法、任务上下文和本地验证结果。方法引用和执行反馈接口已冻结，试运行与发布工作可以独立推进。

每份报告关联一个精确的任务、方案版本和方法版本。报告为本地只读视图，保留 PlanIssue 的 `code`、`field` 与原因。现有 AnalysisPlan JSON 和 SQLite 保存方式保持原契约。前端可按 `kind` 选择交互组件。

| kind | 来源 | 可选值 | 阻断 |
|---|---|---|---|
| `goal` | 任务目标上的本地诊断 | 用户补充目标 | 确认 |
| `input` | 方法声明的输入角色上的诊断 | 同任务、目标、方法和已选资产快照中标记 READY 的精确资产引用 | 确认 |
| `option` | 方法声明的参数上的诊断 | 契约声明的枚举值、布尔类型的两个值 | 确认 |
| `validation` | 其他确定性诊断 | 按诊断调整草案 | 确认 |
| `confirmation` | 无未解决诊断的草案 | 用户显式确认 | 执行 |

每个项目包含 `required` 与 `blocks`。未知值保持空选择列表。数值、坐标系、路径和资产版本由用户或本地确定性规则提供。每个验证项目均对应草案中原有的 PlanIssue。目标含义确实不清楚时，本地流程可在草案写入 `GOAL_AMBIGUOUS`。模型返回的未验证字段不能自行写入草案、完成确认或执行 GIS。

有未解决问题时状态为 `blocked`，问题写入 `AnalysisPlan.issues`，V1 确认守卫拒绝此版本。通过草案校验后状态为 `ready_for_confirmation`，此时仅展示执行前确认。它属于独立澄清视图，写入 `issues` 会阻断合法确认。已经确认的版本状态为 `confirmed` 且报告无项目。

后续会话只从显式用户回答创建新草案版本，由本地服务重新评估。新请求应核对任务、方案版本和方法版本。所有修改通过 V1 确认和运行流程。P15-01 交付模型、Schema 及本地投影。P15-02 接入会话、修订和工作台。澄清报告可能包含本地诊断文本，当前出站模型契约仍以既有字段白名单为准。
