# P15-07 第二模型入口决策

GeoPilot 支持显式配置本机 Chat Completions 兼容服务。启动时在现有 Ollama 入口与本机兼容入口之间选择。未配置模型时工作台进入手工流程。兼容目标是能够在本机提供 `/v1/chat/completions` JSON 模式的运行服务，例如 llama.cpp。 [llama.cpp 服务端协议](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#post-v1chatcompletions-openai-compatible-chat-completions-api)

| 评估项 | 决策 |
|---|---|
| 结构化输出 | 发送非流式 JSON 模式请求。接受一个正常结束的 assistant 文本结果。现有本地解析器检查方法、选项和数据边界。不同服务支持的 JSON Schema 子集有差异，本轮采用 JSON 模式与本地严格校验。 |
| 超时 | 沿用已有整次 HTTP 尝试的截止时间，包含响应持续分片写入的情形。兼容入口与 Ollama 共用回环传输和 1 MiB 响应上限。 |
| 限流 | HTTP 429 映射到既有 `MODEL_RATE_LIMITED`，工作台仍可生成手工草稿。每次建议沿用现有客户端至多两次尝试。部署者可在所选本机服务配置并发和队列容量。 |
| 费用与资源 | 单次请求声明最多生成 768 tokens。兼容入口的 GeoPilot 连接目标为 `127.0.0.1`。本机推理仍占用 CPU、GPU 和显存。兼容服务自身的计费与转发策略属于其部署配置。 |
| 凭据 | 仅启用兼容模式时读取 `GEOPILOT_CHAT_COMPLETIONS_API_KEY`。密钥放在 HTTP Authorization 请求头。返回的异常使用固定错误码和消息，HTTP 错误体不回显。 |

启动后端时追加 `--chat-completions-model <本机模型别名>`，端口默认为 8080，可用 `--chat-completions-port` 指定。原有 `--model-timeout` 继续控制单次尝试的截止时间。兼容模式只连接本机固定协议和路径，并在建连前校验序列化后的模型请求。模型建议仍经本地校验和用户选择进入草稿。

本次验收使用真实回环 HTTP 的合成服务，覆盖协议和 GeoPilot 的行为。具体 llama.cpp 版本、模型权重的建议质量和本机吞吐需用实际部署配置另测。托管供应商的账户密钥管理、费用预算与出站审批留待相关部署决策。
