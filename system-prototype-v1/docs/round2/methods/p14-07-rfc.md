# P14-07 本机方法发布契约

主控设计。实施以 P14-05 和 P14-06 签收为前置。发布状态属于本机方法目录，持久化采用版本化 JSON 台账。现有 YAML 内置方法沿用 V1 目录，已有数据库、运行目录和成果不会迁移。

## 审批与变更

准备审核时，用候选方法文件和受指纹保护的样例包调用现有隔离试跑。正例必须执行成功，产物通过原生检查和独立参考。包中声明的失败用例须在约定阶段阻断。审核材料绑定精确方法、候选字节、样例清单、有效配置与证据指纹。维护者阅读实际结果并显式批准该摘要，记录审批者和理由。发布时复核审批对象，实际重跑关键试验，拒绝候选、包或环境输入发生的未审核变化。手写的通过标记不作为试跑证明。

保留每份原始报告的路径和 SHA-256，并生成可重放的规范摘要。摘要包括方法、包与配置指纹、运行环境以及逐样例的裁定。运行 ID、临时路径、耗时和可变的 GeoPackage 文件头留在原报告。发布使用复验通过的同一份候选字节，并确认目标安装的配置和执行器与审核环境相符。

发布只添加一个新的精确方法定义。与现有方法引用重复、替换历史版本、静态检查失败或缺少审批时拒绝写入。启用、禁用和回滚通过新的台账事件记录，包含操作、精确引用、理由、审批记录与时间。台账先完整验证再原子替换，以同一目录的排他锁保护读改写。同一版本的配置保持可解析。

## 目录与历史

运行服务启动时读取一致的目录快照。新草案和模型候选只提供已启用的版本，确认旧草案时同样核对该精确方法是否仍启用。已确认的方案、运行证据和成果继续使用其记录的精确版本。禁用或回滚只改变后续选择资格。需要激活上一个精确版本时明确记录来源和目标，并重新核对审批。

本机维护者通过开发者 CLI 操作台账，服务重启后加载更新。原型仍在本机信任边界内，审批者字段为本机维护者的明确声明。产品级身份认证与远程发布由后续发布范围决定。
