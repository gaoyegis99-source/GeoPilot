# P14-08 路网最短路径试点

`road-network-shortest-path@1` 在已节点化的二维无向线路网络上按投影米长寻找最短路径，复用 V1 的资产登记、草稿、确认、调度、运行和成果检查。发布配置引用一个可由现有目录发现的 Python 工人。

## 输入和成果

- `network` 为 LineString 图层，`source_feature_id` 必须是唯一的非空字符串。每条线须有效、简单、具有有限二维坐标和正长度，端点须不同。多个线路可以共享完全相等的端点。内部交叉、端点落在另一条边内部和线路重叠会被拒绝。
- `start` 和 `end` 各是仅含一个二维 Point 的图层。三层都须使用与明确指定的 `target_crs` 等价的投影。V1 校验投影的米单位、覆盖范围和局部尺度。输入需在运行前准备到同一个合适的 CRS。
- `snap_tolerance_m` 为非负米数，包含边界。端点吸附到最近的已有网络节点。范围外、多个等距最近节点、起终点落在同一节点和节点间断连均会阻断。
- `route_edges` 为 GeoPackage 线路成果，每个行进边保留 `source_feature_id`，并记录从 1 开始的 `sequence` 和 `distance_m`。坐标沿行进方向排列。
- `route_summary` 为 JSON，记录 CRS、米单位、按行进顺序列出的边、总长度以及两个吸附节点的坐标和偏移。总长度是线路米长之和，吸附偏移单独记录。

边权为完整线长。等距离候选按节点坐标和边 ID 的固定顺序处理，保留首先到达的前驱。网络采用无向边和精确端点坐标，适用于已完成拓扑准备的本地路网。单行、转向、速度、时间与车种等约束不属于此方法的输入契约。

## 样例和工作台步骤

样例包为 `tests/method_dev/fixtures/road-network-shortest-path`。手算线路从西端经过中点到东端，两段分别为 30 m，总长 60 m。北侧备选由两条 3–4–5 比例的斜边组成，各 50 m。起点与终点各偏离吸附节点 5 m，恰在容差边界。EPSG:3857 变体只替换起点图层，指定 V1 草稿阶段的 `MEASUREMENT_POLICY_REJECTED`。 [样例清单](../../../tests/method_dev/fixtures/road-network-shortest-path/manifest.json)

1. 在工作台登记 `inputs/network.geojson`、`inputs/start.geojson`、`inputs/end.geojson`。
2. 选择「路网最短路径」方法 `road-network-shortest-path@1`，给三个角色选择对应资产版本。
3. 将「米制投影坐标参考系」填为 `EPSG:32650`，将「最大吸附距离」填为 5 m，生成并确认草稿。
4. 开始运行，在检查中核对投影适用性和成果 CRS，再打开两项成果。JSON 的 `edge_ids` 为 `["west", "east"]`，总长为 60 m。
