# 工作台体验补充观察（主持人用）

在标准六项任务记录收表后，经参与者同意，可沿用当前浏览器项目和道路缓冲统计 v3 样例继续观察。先留存标准任务的观察表与已下载的原始 CSV。有成功运行时，记住该次运行供后续辨认。参与者只听下表的任务提示，主持人按观察点记录实际操作。 [标准主持手册](moderator.md) · [受试任务单](participant-task.md) · [浏览器复验证据](p16-ux-follow-up.md)

| 场景 | 主持准备与任务提示 | 观察点 |
| --- | --- | --- |
| 草稿恢复 | 主持在当前方法表单中只把距离坐标参考系改为 `EPSG:3857`，点击「生成草稿」。把控制交还给参与者，请其说明提示的意思，并把草稿修到可以确认。 | 「待补项」提示测量 CRS 不适用，确认禁用。观察参与者能否找到「定位」、识别聚焦的距离坐标参考系、改回任务单的 `EPSG:32650`，并按「表单已修改，请先生成草稿」的提示重新生成、确认。记录是否需要协助，以及四项资产选择是否保留。 |
| 刷新与取消 | 从修正并确认的方案开始一次普通运行。请参与者在排队或计算中刷新，说明刷新后看到的进度，并在计算仍可取消时停止本次运行。取消后请其恢复任务。 | 刷新前后观察运行号、执行状态和可见步骤，以运行号判断是否回到同一次运行，步骤可以随处理推进。计算阶段观察「取消运行」「已请求取消」「已取消」及参与者对三者的理解。到达取消终态后，观察其能否找到步骤日志和「按原方案重新运行」，以及重跑是否产生不同运行号。若未及点击时计算已结束或进入成果检查，记下实际状态，取消环节记未尝试。若已提交取消，记录实际终态。 |
| 辨认历史成果 | 当本次补充操作产生第二次成功且检查通过的运行后，请参与者打开较早的成功运行，找到该次的分区统计 CSV，并说明如何确认归属。 | 观察其能否在「运行历史」中区分执行和检查状态，并用选中的历史记录、「来源详情」中的运行号或 `statistics-<运行号>.csv` 识别文件。记下使用的线索以及是否误选较新的成果。若只有一次可用的成功运行，记录原因，历史切换记未尝试。 |

在同一匿名编号的主持人简记中，为每个补充场景记下实际状态或提示原话、参与者采取的动作，以及求助、协助和恢复情况。结果与事件沿用记录格式中的 `outcome`、`help_requests`、`assisted`、`errors` 含义。临时项目中可核对运行号，匿名简记只需写「同一次」或「不同次」。补充下载可留在主持目录的单独位置，标准任务的 `U001.csv` 等原始文件继续用于六项汇总。 [匿名记录格式](observations.md)

本表可观察受控草稿错误的定位、普通运行的状态恢复及历史成果归属。运行很快结束时，可能只观察到部分阶段。其他错误路径、长任务规模和完成时间仍以实际参与者会话及相应验证为据。
