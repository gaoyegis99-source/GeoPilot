# GeoPilot 第二轮多智能体开发总控计划

## 总目标
在不重做 V1 已验收能力的前提下，提升交付可信度、运行可靠性、性能可测性、方法扩展生态、Agent 自主分析和产品化能力。

## 事实基线
- 仓库：`gaoyegis99-source/GeoPilot`
- 分支：`main`
- 原型目录：`system-prototype-v1`
- V1 看板：122 项历史任务全部 ACCEPTED
- 最新需求矩阵：40 PASS
- 固定用例台账：T01—T16 PASS
- P12 审计发现：见 `01_AUDIT/P12_DEEP_AUDIT_REPORT.md`

## 原则
1. P0—P11 是历史基线，不重新开发。
2. 每项第二轮任务先读现有源码和验收证据。
3. 先基准测量，再做性能优化。
4. 未验证不等于缺陷；文档声称不等于独立复跑。
5. 不引入远程多用户架构，除非另有产品决策。
6. LLM 不得绕过本地校验、用户确认和执行审批。
7. 不自动信任脚本或自动发布未经验证的方法。
8. 每个任务有输入、输出、文件范围、依赖、命令和验收标准。
9. Agent 自报完成只能进入 REVIEW。
10. 建议建立 round2 分支和独立 worktree，不直接开发 main。

## 阶段
P12 审计闭环必须先完成。P12 后 P13 与 P14 可部分并行。P15 依赖 P14 的方法接口和 P13 的执行反馈。P16 依赖性能、生态、部署和工作台技术验证证据。 [P16 适用范围](../03_PHASES/P16_产品化与用户验证.md)

## Agent
A 平台/数据；B GIS/执行；C 方法生态；D 调度/可靠性；E 前端/UX；F QA/性能；G Agent/LLM。主控负责公共契约、冲突和验收。

## 执行规则
第一轮只执行 P12-01 至 P12-04。完成后复核发现。第二轮执行 P12-05 至 P12-11。P12-12 主控签收后才放行后续阶段。

## 完成定义
每项任务交付 diff、测试命令、原始结果、证据路径、接口影响和回滚说明。结果绑定 commit SHA。
