# GeoPilot Vibecoding 多智能体开发计划

本目录是基于《GeoPilot 产品需求规格与系统详细设计报告 V2.0》整理的可执行开发计划，不是 GeoPilot 运行期 Agent 架构。目标是让本地 Codex 按小任务、接口先行、并行开发、证据验收的方式完成原型。

## 开始方式
1. 将本目录放入 GeoPilot 项目的计划目录。
2. 在项目根目录启动 Codex，先让主控读取 `00_GOVERNANCE/00_MASTER_PLAN.md`。
3. 主控必须先完成仓库审计和路径映射，不得假定本计划中的 `src/...` 是现有真实路径。
4. 先执行 P0；只有 P0 证据通过后才解锁 P1。
5. 每个原子任务对应 `04_TASKS/<阶段>/<任务ID>.md`，一项一项派发、测试、验收。
6. 任务状态由主控更新到 `06_PROGRESS/TASK_BOARD.md`，并把证据写入 `06_PROGRESS/ACCEPTANCE_LOG.md`。

## 计划结构
- `00_GOVERNANCE/`：总控指令、并行规则、状态机、使用说明。
- `01_ARCHITECTURE/`：模块边界、接口契约、依赖图、文件所有权。
- `02_AGENT_PLAYBOOKS/`：各专业 Agent 的角色提示词。
- `03_STAGES/`：P0—P11 阶段目标、任务索引和退出标准。
- `04_TASKS/`：每个原子任务独立 Codex 指令。
- `05_ACCEPTANCE/`：统一验收模板、门禁和测试原则。
- `06_PROGRESS/`：任务看板、依赖状态、验收日志、阻塞记录。

## 重要约束
本计划不代表当前代码已经存在，也不保证当前机器已安装所有依赖。所有路径均须由 P0 仓库审计映射到实际项目结构；测试命令须按实际项目包管理器/目录调整并记录。任何未执行的测试必须标记 NOT_RUN，不能写 PASS。
