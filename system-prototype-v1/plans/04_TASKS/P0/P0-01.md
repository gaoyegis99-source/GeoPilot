# P0-01 — 现有项目结构审计

## 1. Codex 执行指令
你是本任务的实现 Agent。请先检查当前仓库和既有实现，再完成以下单一目标：**检查代码仓库、已有计划、入口和现有功能，形成不覆盖既有成果的基线。**

必须遵循：
- 阅读总控计划、公共契约、文件所有权及依赖任务的 ACCEPTED 记录。
- 先复用已有实现；不要假定逻辑路径就是实际路径。
- 只修改本任务范围内文件；需要改公共契约时先向主控提案。
- 先写/补充测试，再实现最小功能；不要删除或放宽已有断言。
- 不得用 Mock 代替本任务要求的真实 GIS 验证。
- 完成后提交测试证据，状态只能建议 REVIEW。

## 2. 目标与范围
检查代码仓库、已有计划、入口和现有功能，形成不覆盖既有成果的基线。

**允许修改范围（逻辑路径，P0 后映射真实路径）：**
只读整个仓库；新增 docs/baseline/PROJECT_AUDIT.md。

**明确不在本任务范围：**
- 不重构无关模块。
- 不修改公共 API/schema/数据库结构，除非任务本身明确要求且主控批准。
- 不扩展到后续任务的业务能力。
- 不改变 GeoPilot V2.0 产品目标。

## 3. 前置依赖
无；先读取产品设计 PDF 与仓库现状。

依赖未 ACCEPTED 时，本任务必须标记 BLOCKED，不得用临时假实现绕过。

## 4. 输入与交付
**输入/上下文：** 按任务目标读取已有模块、相关配置、样本和接口契约。

**必须交付：**
审计报告、目录树、风险清单。

此外必须提交：
- 新增/修改/删除文件清单；
- 实际执行命令与原始输出摘要；
- 接口影响说明；
- 未解决问题和限制；
- 对应验收记录。

## 5. 测试命令
```bash
`git status --short`；按仓库实际测试入口执行一次基线测试；无测试时记录 NOT_AVAILABLE。
```
若仓库实际测试入口不同，先在 P0 路径映射中记录等价命令，再执行并在报告中说明。命令未执行必须标记 NOT_RUN。

## 6. 验收标准
- [ ] 项目目录、入口、依赖、已有测试、未完成项均有证据；未修改业务代码。

## 7. 失败与阻塞处理
遇到缺依赖、接口歧义、样本不足、真实 GIS 环境不可用或需要越权修改时：
1. 停止扩大实现；
2. 记录复现步骤、错误输出和受影响范围；
3. 提交 BLOCKER，给出最小替代方案及其风险；
4. 等待主控决策。
