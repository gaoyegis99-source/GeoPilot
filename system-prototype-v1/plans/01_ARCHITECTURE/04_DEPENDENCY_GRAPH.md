# 阶段依赖与并行策略

## 主链
P0 → P1 → P2 → P3 → P4 → P5。

## 扩展分支
- P6 矢量：计算验证可在 P3 后推进；UI 联调需 P5。
- P7 DEM/栅格：依赖 P4/P5 的执行和结果通路。
- P8 遥感：依赖 P7 的栅格基础。
- P9 模型入口：可在 P5 后对已验收方法并行开发；最终必须进入统一 AnalysisPlan。
- P10 脚本/PostGIS：依赖 P4 的运行与文件交接；PostGIS 是可选项。
- P11：依赖本轮选定能力和测试证据。

## 允许并行的例子
- P0-03 QGIS smoke 与 P0-04 Python smoke。
- P1-03/04/05 数据读取器在 DataAsset 模型冻结后并行。
- P2-05 距离策略与 P2-06 面积策略并行。
- P3-02 方法加载与 P3-06 方案模型在接口冻结后并行。
- P4-12/13/14 三类检查器在报告模型冻结后并行。
- P5-02/03/08 前端资产、方法、地图组件在 API 契约稳定后并行。
- P6 不同归属算法在共享输入/输出契约冻结后并行。

## 禁止并行
同一公共模型、数据库迁移、核心调度器、同一前端状态容器不可由多个 Agent 同时改写。若发生冲突，暂停任务并由主控重新分配。
