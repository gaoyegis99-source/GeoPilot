# GeoPilot 多智能体并行开发总控计划

## 1. 使命
依据 GeoPilot V2.0 设计，组织本地 Vibecoding/Codex 开发。产品目标保持为单用户、本机 Web GIS 原型：自然语言/手工任务整理 → 数据上下文 → 可确认分析方案 → 本地 QGIS/Python 执行 → 规则检查 → 成果查看与来源追踪。

## 2. 不得改变的产品基线
- Python + Pydantic 组织业务对象和确定性控制流程。
- QGIS Processing 与 Python 子进程执行 GIS 计算。
- SQLite 保存元数据、方案、运行和检查状态；大空间数据保存在文件。
- MapLibre 是首版主地图引擎。
- 方法定义保存输入角色、关键选项、固定步骤、成果和检查规则。
- 工具契约保存实现、输入输出、参数和前提。
- 执行状态与检查状态分离。
- 外部模型只接收允许的结构/统计摘要；几何、坐标数组、原始样本、原始文件和本机路径不得外发。
- 模型建议不能绕过本地校验、用户确认和固定步骤。
- 不为了多智能体开发而引入微服务或产品运行期多 Agent。

## 3. 开发组织
主控 Agent 是唯一架构协调者、任务调度者和最终验收者。专业 Agent 分工：
A 数据/存储；B GIS/执行适配；C 方法/契约/方案；D 调度/运行；E 前端/地图；F 测试/质量；G 模型适配。
每个原子任务必须有唯一代码责任人。测试 Agent 可并行编写测试，但不得与实现 Agent 无约束修改同一文件。

## 4. 任务颗粒度
- 一个原子任务只交付一个可验证的能力。
- 每个任务必须有 objective、scope、out-of-scope、dependencies、inputs、outputs、test commands、acceptance criteria。
- 任务通常在一个短开发—测试—修正周期内完成；如果任务跨越多个独立能力，主控必须继续拆分。
- 任务说明中的 `src/...` 是逻辑路径示例，P0 审计后必须映射真实目录。

## 5. 并行规则
允许不同模块、独立测试数据、文档审计并行；接口冻结后允许前后端并行。禁止多人同时改公共模型、数据库迁移、依赖清单或同一生产文件。共享文件变更必须先提案，主控批准并指定唯一修改者。
推荐独立 Git worktree/分支；若不能使用，严格执行文件所有权表。

## 6. 任务状态
TODO → DOING → REVIEW → ACCEPTED；另有 BLOCKED、REWORK、NOT_APPLICABLE。
只有主控在查看测试输出和代码差异后才能标记 ACCEPTED。Agent 自报完成只能进入 REVIEW。

## 7. 阶段顺序与并行
P0→P1→P2→P3→P4→P5 为基础主链。P6 可在 P3 后开展算法验证，页面联调依赖 P5。P7 依赖 P4/P5。P8 依赖 P7。P9 可在 P5 后以已验收方法联调。P10 依赖 P4；P11 汇总所有本轮选定能力。局部并行不意味着跳过前置接口/验收。

## 8. 四级验收
L1 原子任务：代码、类型、单测、异常/边界。
L2 模块：模块接口、负向输入、真实适配器 smoke。
L3 集成：跨模块数据、版本、状态、文件引用和故障传播。
L4 产品：真实 GIS 任务、参考结果、页面流程、复现记录。
任何级别不通过均不得放行下游。

## 9. 真实 GIS 验证
Mock 只用于隔离单元测试。关键路径必须至少有真实 QGIS/Python 进程、真实小样本、实际输出文件、日志、退出码和成果检查证据。空间集合/整数计数精确比较；连续数值按预先锁定的单位、绝对/相对容差；栅格先比 CRS、transform、尺寸、分辨率和 NoData，再比共同有效像元。

## 10. 开发启动顺序
第一轮只执行 P0-01 仓库审计、P0-02 环境盘点、P0-07 测试基线。主控根据真实仓库更新路径映射和文件所有权，再并行执行 P0-03—P0-06。P0 退出后才进入 P1。

## 11. 完成定义
每项任务必须交付：修改文件清单、实现说明、实际执行命令、原始测试结果、接口影响、剩余问题、验收记录。每阶段另交付阶段报告。没有实际测试输出不得声称通过。

## 12. 冲突处理
发现设计文档歧义、接口冲突、缺少依赖或无法实现时，Agent 停止扩大修改，提交 BLOCKER：现象、复现、受影响接口、可选方案、推荐方案。主控决定是否修订设计，并更新变更记录。
