# 如何使用本开发计划

## 第一次启动
在项目根目录让 Codex 执行：
1. 阅读本文件及 `00_MASTER_PLAN.md`。
2. 阅读 `01_ARCHITECTURE/`。
3. 检查仓库状态、分支、未提交改动和已有计划。
4. 执行 P0-01、P0-02、P0-07；不要先写业务代码。
5. 输出真实路径映射、现有能力复用表、待建模块表和文件所有权提案。

## 每次派发
主控从 `06_PROGRESS/TASK_BOARD.md` 选择所有依赖已 ACCEPTED 且没有文件冲突的任务。向执行 Agent 提供任务文件全文、对应接口文件、已验收依赖证据和明确文件范围。

## Agent 提交格式
- Task ID / Agent
- 完成内容
- 修改文件（新增/修改/删除分别列出）
- 执行命令及原始摘要
- 测试通过/失败/未运行
- 接口变更（无则写无）
- 未解决问题
- 建议验收结论（不得自行写 ACCEPTED）

## 主控验收
主控检查 diff、测试命令是否真实执行、是否超出 scope、是否破坏既有测试；必要时由 F Agent 独立复核。通过后更新任务板和验收日志。

## 本地环境命令调整
计划中的 pytest 路径是预期测试路径。若仓库使用 unittest、uv、poetry、pnpm 或其他工具，先在 P0 记录项目实际命令，再对每个任务保持可复现的等价命令。不得静默省略测试。
